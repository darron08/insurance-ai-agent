# M2：条款切分

本阶段数据流：

```text
M1 page JSON → 输入与质量校验 → 章节/条款识别 → 超长文本切分
             → ChunkedDocument → 临时 JSON → 完整 Chunk JSON
```

M2 将解析和切分保留为两个可单独运行的步骤。这样可以先判断 PDF 文字是否正确，再判断 Chunk 边界是否合理；如果切分策略改变，也能复用 M1 输出而不重新解析 PDF。

## 运行方式

先执行 M1 导入并记下终端显示的输出路径：

```bash
go run ./cmd/ingest \
  --file ./testdata/sample.pdf \
  --product-id demo \
  --document-name "自建解析测试资料" \
  --output ./var/imports
```

再切分该 JSON：

```bash
go run ./cmd/chunk \
  --input ./var/imports/<上一步输出的文件>.json \
  --output ./var/chunks
```

## 阅读顺序

1. `cmd/chunk/main.go`：命令如何处理参数、退出码和终端摘要。
2. `internal/chunker/service.go`：M1 JSON 如何严格读取、调用切分器并原子落盘。
3. `internal/chunker/chunker.go`：文档校验、结构识别、跨页状态和长度切分。
4. `internal/document/model.go`：Chunk 与 ChunkedDocument 的 JSON 契约。
5. `internal/chunker/chunker_test.go`：规则如何由合成文本和真实保险条款共同约束。

## 为什么核心接口接收 Document

文件命令只是 M2 的调试和学习入口。真正的切分器接收 `document.Document`，不读取 PDF，也不知道命令行参数。后续加入一键导入时，解析服务可以直接把内存中的 Document 传给切分器：

```text
ingest CLI
  → 解析得到 Document
  → 保存 page JSON
  → Split(Document)
  → 保存 chunk JSON
  → M3 状态持久化
  → M4 Embedding 与索引
```

独立命令仍然有价值：它允许只重跑切分、比较策略，并保留可审计的页面级中间结果。

## 结构优先规则

`clause-aware-v1` 识别两种常见格式：

- 小数编号，例如 `1.1 合同构成`、`8.17物理治疗`。
- 中文条款编号，例如 `第一条`、`第二十七条`。

条款前长度不超过 30 个 Unicode 字符、没有句末标点的独立短行，可以成为章节标题。识别只使用明确的文本形态，不根据保险语义猜测。标题原文仍保留在 Chunk 正文中。

遇到 `目录`、`目 录` 或 `条款目录` 后，该物理页剩余内容作为普通文本保存，不再识别条款编号，防止目录项产生虚假条款。下一页恢复正常识别；目录前已经识别的跨页条款状态不会丢失。

## 页码和跨页续文

一个 Chunk 只属于一个物理 PDF 页。若条款从第 2 页延续到第 3 页，第 3 页开头会继承该条款的 `section_title` 和 `clause_id`，但产生新的 Chunk。`part_index` 和 `part_count` 表达这些片段属于同一条款实例。

空白页不产生空 Chunk，但仍保留在源 Document 中，因此后续页面继续使用原物理页码。

## 超长条款

单个页面中的结构块不超过 800 个 Unicode 字符时保持完整。超长时按以下优先级寻找边界：

1. 空行。
2. 普通换行。
3. 句末标点。
4. Unicode 字符边界。

相邻子块最多重叠 100 字符，重叠仅发生在同一条款、同一物理页面内。字符计数使用 Unicode 码点而不是 UTF-8 字节数，避免把中文字符切坏。

## 输入质量与失败行为

切分前会重新验证 M1 可观察契约：产品和文档名称、来源信息、64 位 SHA-256、`quality.status`、页数、连续物理页码、字符总数、文本页统计和替换字符。手工损坏或不完整的 JSON 会在创建输出目录前失败。

落盘沿用 M1 的方式：先写临时文件，完整编码并关闭后再改名为 `.json`。重复切分保留以前的输出；中途失败不会留下最终结果文件。

## 测试覆盖

```bash
go test -v ./...
```

- 小数编号、中文条款编号和章节标题。
- 目录防误判、无编号前言和正文保留。
- 跨页续文、空白页和物理页码。
- 800 字符上限、100 字符重叠和 Unicode 安全。
- 错误 JSON、未知字段、多个 JSON 值、质量失败和输出失败。
- 两份真实保险条款中的中文顺序、章节、条款编号、页码和字符质量。

## 动手实验

1. 在合成文本中把 `1.1` 改为普通标题，观察 `clause_id` 如何变化。
2. 将一条正文扩展到 800 字符上下，比较 Chunk 数量、`part_index` 和重叠内容。
3. 在条款中间加入空白页，确认下一页继承条款编号但物理页码不压缩。
4. 修改章节标题的句末标点，运行测试并观察确定性启发式的边界。

## 当前限制

- 无编号或排版异常的条款可能作为普通文本 Chunk 输出。
- M1 已经把表格转换成纯文本，M2 不重建行列结构。
- 固定的 800/100 参数是首个可比较基线，还不是检索质量最优结论。
- `document_id`、处理状态、幂等、失败重试和一键流水线从 M3 起逐步加入。
- 自动切分通过不代表保险条款经过人工法律审校，真实资料仍需抽页检查。
