# M1：PDF 命令与解析

本阶段数据流：

```text
CLI 参数 → 参数校验与文件打开 → SHA-256 → PDF 逐页解析
        → Document → 临时 JSON → 完整 JSON 与终端摘要
```

## 阅读顺序

1. `cmd/ingest/main.go`：先看 `run`，了解参数、错误显示和退出码；`main` 只负责退出。
2. `internal/ingest/service.go`：阅读 `Run`，顺着一次导入追踪输入检查、哈希、解析、JSON 保存。
3. `internal/document/model.go`：确认文档、元数据、页之间的关系。
4. `internal/parser/parser.go`：理解流程为什么只依赖 `Parser`，而不直接依赖某个 PDF 库。
5. `internal/parser/pdf.go` 和 `pdf_extract.py`：了解 Go 如何管理 Python 子进程，以及 `pdfplumber` 如何逐页提取文本。
6. `internal/ingest/service_test.go`：看测试如何验证输出，并保证失败时不会产生成功文件。
7. `internal/parser/pdf_test.go` 与 `cmd/ingest/main_test.go`：看页码、中文、空白页、损坏文件和退出码如何验证。

## 值得停下来理解的地方

### PDF 为什么不像 TXT

PDF 主要存储文字绘制指令、字体和坐标，而不是天然的段落数组。解析库负责把字体代码转换为文字，并根据内容流恢复阅读顺序。项目使用 `pdfplumber`，是因为原纯 Go 解析器在真实中文条款中产生替换字符、倒序文字和双栏交错。后续 Chunking 的输入是否可靠，取决于这里提取的文本是否正确。

### 为什么保留页码

提取结果必须能回到原文。M1 将物理页码保留在每个 `Page` 中；M2 的 Chunk 将继承这个信息；后续回答才能显示来源。空白页不能直接删除，否则容易导致后续页码错位。

### 为什么需要接口

`Service` 接收 `Parser`，不直接接触第三方库的数据类型。Go 适配器启动带超时的 Python 子进程，Python 只返回页面、引擎版本和清理计数。更换解析器时实现相同的 `Parse` 方法即可，业务流程不会接触 `pdfplumber` 的类型。

### 为什么要有质量门槛

“成功打开 PDF”不等于“文本可以用于保险问答”。导入会拒绝全文为空或包含 `U+FFFD` 替换字符的结果，并在成功 JSON 中记录文本页、空白页和被清理的私用区装饰字符。自动门槛无法证明复杂表格绝对正确，真实条款仍要抽页核验。

### 哈希与幂等的区别

SHA-256 对原始文件字节计算；相同字节得到相同结果。校验值只是身份依据，不会自动防止重复处理。M1 每次都执行解析并保存独立结果；M3 再把校验值与产品、版本等业务规则结合起来，决定是否跳过、拒绝或重建。

### 为什么失败不能输出成功文件

输入校验、解析和全文为空检查都在创建输出目录之前执行。序列化阶段先写 `.tmp`，成功关闭后改名；中途出错会清理临时文件。这样阅读输出目录时不会把半份 JSON 当作完成的导入。

### 为什么限制解析时间

损坏或构造异常的 PDF 可能让解析器长时间运行。Go 适配器为 Python 子进程设置两分钟上限，超时后终止解析并返回普通错误，不生成最终 JSON。

## 测试覆盖

```bash
go test -v ./...
```

- 三页英文与中文文本、物理页码和空白页位置。
- 完整 JSON 可反序列化，包含元数据、校验值、质量、时间和解析器版本。
- 重复导入校验值一致，原结果保留。
- 文件不存在、错误扩展名、伪造 PDF、损坏结构、空文本、替换字符、缺 Python、缺 `pdfplumber`、超时、缺元数据和错误来源地址。
- CLI 成功、帮助、未知参数、位置参数和必填参数遗漏。

`internal/testpdf/fixture.go` 构造测试专用 PDF，包括中文字体到 Unicode 的映射。测试无需访问互联网或模型 API，但运行前需要安装 `requirements.txt`。

`testdata/sample.pdf` 由项目自建，可用以下命令重新生成：

```bash
go run ./testdata/generate.go
```

生成器会替换该示例文件。两份真实保险 PDF 位于 `testdata/real/`，同时作为字体和双栏顺序的离线回归样本。

## 动手实验

1. 修改 `testdata/generate.go` 中第二页的英文，重新生成样本并导入。检查第二页正文与文件 SHA-256 是否变化。
2. 保持 PDF 不变，只修改 `--document-name`。观察 SHA-256 不变，但元数据和导入时间变化。
3. 将测试中的中间页设为空白，确认第三页仍编号为 3。
4. 给来源地址校验增加一个失败用例，再运行所有测试。
